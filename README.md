# Algorithm Arena

เว็บเกมฝึกอัลกอริทึมสำหรับโครงงาน Object-Oriented Programming พัฒนาฝั่งเซิร์ฟเวอร์ด้วย **Java 21+** และเก็บข้อมูลจริงด้วย **H2 Database ผ่าน JDBC** หน้าจอใช้ HTML, CSS และ JavaScript

## เปิดเว็บออนไลน์ด้วย Render + Neon

รองรับ PostgreSQL ผ่าน `JDBC_DATABASE_URL`, `DB_USER`, `DB_PASSWORD` แล้ว
มี Dockerfile และ render.yaml พร้อมตั้งค่าสำหรับ Render Free
อ่านขั้นตอนใน [คู่มือ Deploy](docs/DEPLOY_RENDER_NEON.md)
เมื่อไม่ได้ตั้ง JDBC_DATABASE_URL จะใช้ H2 บนเครื่องตามเดิม
ข้อมูลเดิมจาก H2 ไม่ถูกย้ายไป PostgreSQL อัตโนมัติ

## เริ่มใช้งาน

ต้องมี **JDK 21 หรือใหม่กว่า** (ต้องมีทั้ง `java` และ `javac`) เครื่องที่ใช้พัฒนาได้ทดสอบด้วย JDK 25 โดยคอมไพล์ให้รองรับ Java 21

### macOS / Linux

เปิด Terminal ที่โฟลเดอร์นี้ แล้วใช้:

```sh
sh run.sh
```

บน macOS สามารถลองดับเบิลคลิก `Start.command` ได้ หากระบบไม่อนุญาตให้เปิด ให้ใช้คำสั่งข้างต้นแทน

### Windows

ดับเบิลคลิก `run.bat` หรือรันไฟล์นี้จาก Command Prompt หากไม่พบ Java ต้องติดตั้ง JDK และตั้งค่า PATH ก่อน

เปิด **http://localhost:8080** ในเบราว์เซอร์ แล้วสมัครบัญชีใหม่ ไม่ต้องติดตั้ง Maven, MySQL หรือดาวน์โหลดไลบรารีเพิ่ม เพราะแนบ H2 JAR มาแล้ว

หยุดเว็บด้วย Ctrl+C ในหน้าต่างที่รัน หากพอร์ต 8080 ถูกใช้อยู่ บน macOS / Linux ใช้ `PORT=8081 sh run.sh` แล้วเปิด http://localhost:8081

## สิ่งที่ทำได้

- สมัครสมาชิก / เข้าสู่ระบบ / ออกจากระบบ
- เล่น Bubble Sort, Stack และ Queue รวม 15 ด่าน
- แอนิเมชัน Bubble Sort เปรียบเทียบและสลับตำแหน่ง พร้อมภาพ PUSH/POP ของ Stack และ ENQUEUE/DEQUEUE ของ Queue
- ดูภาพซ้ำ ปรับความเร็ว 0.5× / 1× / 2× หรือข้ามภาพได้ รองรับการตั้งค่าลดภาพเคลื่อนไหวของอุปกรณ์
- แผงตัวอย่างโค้ด Java ข้างเกมทั้งสามสนาม ไฮไลต์บรรทัดตามภาพ พร้อมค่าตัวแปรและคำอธิบายไทยทีละส่วน
- รับเฉลยและเหตุผลหลังตอบแต่ละขั้นตอน ตอบได้ครั้งเดียวต่อขั้นตอน
- คะแนนเต็ม 1,000 คิดจากสัดส่วนคำตอบถูก เซิร์ฟเวอร์คำนวณเอง
- นาฬิกาเริ่มตั้งแต่เริ่มด่าน รวมเวลาอ่านเฉลย ไม่มีเวลาบังคับจบ
- สรุปผล เหรียญ และทบทวนคำตอบย้อนหลัง
- ตารางคะแนนแยกตามสนามและด่าน เก็บผลงานดีที่สุดของแต่ละคน คะแนนเท่ากันใช้เวลาน้อยกว่าอันดับดีกว่า
- ประวัติส่วนตัวและสถิติจาก 50 รอบที่เล่นจบล่าสุด
- เล่นเกมที่ค้างต่อหลังรีเฟรชหรือเริ่มเซิร์ฟเวอร์ใหม่ได้ (ต้องเข้าสู่ระบบใหม่หลังเซิร์ฟเวอร์เริ่มใหม่)
- การเริ่มเกมใหม่ยุติเกมเก่า รอบที่ไม่จบไม่เข้าสู่ตารางอันดับ
- หน้าจอปรับตามขนาดคอมพิวเตอร์และมือถือ

## ฐานข้อมูลจริงอยู่ที่ไหน

หลังรันครั้งแรกจะสร้างไฟล์ **`data/arena.mv.db`** ไม่ใช่ข้อมูลใน localStorage หรือไฟล์ JSON

| ตาราง | หน้าที่ |
|---|---|
| `users` | บัญชีผู้ใช้และค่าแฮชรหัสผ่าน |
| `challenges` | ข้อมูลสนามและด่าน 15 รายการ |
| `attempts` | รอบการเล่น คะแนน เวลา ขั้นตอนปัจจุบัน และสถานะ |
| `answers` | คำตอบรายขั้นตอน ใช้ทบทวนผลย้อนหลัง |

เชื่อมความสัมพันธ์ด้วย Primary Key และ Foreign Key การบันทึกคำตอบและอัปเดตรอบใช้ธุรกรรมเดียวกัน ป้องกันการได้คะแนนซ้ำจากคำตอบขั้นตอนเดียวกัน

## ภาพเคลื่อนไหวระหว่างเล่น

ก่อนตอบ Bubble Sort จะเน้นคู่ที่เปรียบเทียบ ส่วน Stack/Queue จะแสดงการเพิ่มข้อมูลทีละตัว หลังส่งคำตอบแล้วจึงแสดงการสลับหรือการนำข้อมูลออกตามผลที่ถูกต้องจากเซิร์ฟเวอร์ แม้เลือกคำตอบผิด รวมถึงขั้นตอนสุดท้ายของด่าน

ปุ่ม **ดูภาพซ้ำ** เล่นเฉพาะภาพของขั้นตอนปัจจุบัน ไม่ส่งคำตอบใหม่และไม่เพิ่มคะแนน ปุ่ม **ข้ามภาพเคลื่อนไหว** แสดงสถานะปลายทางทันที ความเร็วที่เลือกใช้ต่อในด่านถัดไปจนกว่าจะรีเฟรชหน้า เวลาเล่นยังนับต่อระหว่างดูภาพตามกติกาเดิม

แผง **อ่านโค้ดไปพร้อมกัน** แสดงตัวอย่าง Java แบบย่อ ไฮไลต์ตามการเปรียบเทียบ สลับ เพิ่ม หรือนำข้อมูลออก พร้อมค่าตัวแปรที่เกี่ยวข้อง กด **อธิบายโค้ดทีละส่วน** เพื่ออ่านความหมายของแต่ละช่วง บนจอเล็กแผงโค้ดจะอยู่ใต้กระดานและเลื่อนโค้ดแนวนอนได้ Stack/Queue ใช้ ArrayList ตามแนวทางของเกม ตัวอย่างเพิ่มการตรวจรายการว่างเพื่อให้นำไปศึกษาได้ครบถ้วน

หากเปิดเซิร์ฟเวอร์รุ่นเดิมอยู่ ให้หยุดด้วย Ctrl+C แล้วรัน `sh run.sh` ใหม่ก่อนรีเฟรชหน้า เพื่อโหลด API และไฟล์ `web/visualizer.js` รุ่นใหม่ บัญชี คะแนน และเกมค้างยังอยู่ในฐานข้อมูลเดิม

หากต้องการสำรองข้อมูล ให้หยุดเซิร์ฟเวอร์ก่อน แล้วคัดลอกโฟลเดอร์ `data` ทั้งโฟลเดอร์ อย่าลบไฟล์ฐานข้อมูลหากต้องการเก็บคะแนนเดิม

ตรวจตารางด้วย H2 Shell หลังหยุดเซิร์ฟเวอร์:

```sh
java -cp lib/h2-2.3.232.jar org.h2.tools.Shell -url jdbc:h2:file:./data/arena -user sa -password ""
```

ตัวอย่าง SQL: `SELECT username, created_at FROM users;` และ `SELECT * FROM attempts;`

บน Windows ใช้คำสั่งเดียวกันได้ ควรรันจากโฟลเดอร์โปรเจกต์

## OOP ในโค้ด

| แนวคิด | ตัวอย่างจริง |
|---|---|
| Class / Object | `ChallengeFactory` สร้างวัตถุเกมตามสนามและด่าน |
| Constructor | `new BubbleSortChallenge(1)` กำหนดประเภทและระดับ พร้อมตรวจค่าด่าน |
| Encapsulation | `Challenge` มี `private final type` และ `level`; อ่านผ่านเมธอด และ `Step` เก็บสำเนารายการที่แก้ไขไม่ได้ |
| Abstraction | `Challenge` และ `LinearChallenge` เป็น abstract class กำหนดพฤติกรรมร่วม |
| Inheritance | `BubbleSortChallenge extends Challenge`; `StackChallenge` และ `QueueChallenge` สืบทอดจาก `LinearChallenge` |
| Method overriding | แต่ละคลาสเขียน `buildSteps()`, `title()` และ `concept()`; Stack/Queue เขียน `removeIndex()` ต่างกัน |
| Polymorphism | `GameService` รับวัตถุผ่านชนิด `Challenge` และเรียก `buildSteps()` โดยไม่ต้องเขียนอัลกอริทึมทุกเกมใน service |
| Composition | แต่ละ `Step` เป็นองค์ประกอบข้อมูลของโจทย์ ส่วน `GameService` ใช้ `AttemptRepository` ที่รับผ่าน constructor |

อ่านแผนภาพและแนวทางจัดทำรายงานใน `docs/PROJECT_GUIDE.md`

## โครงสร้างไฟล์

```text
src/arena/             โค้ด Java แยกคลาส
web/                   หน้าจอเว็บ
lib/                   H2 JDBC driver และข้อมูลลิขสิทธิ์
resources/schema.sql   โครงสร้างตารางสำหรับอ้างอิง
resources/data.sql     ข้อมูลด่านเริ่มต้นสำหรับอ้างอิง
docs/                  แผนภาพคลาส ฐานข้อมูล และแนวทางเอกสาร
test/                  ชุดตรวจอัลกอริทึมและระบบจริง
run.sh / run.bat        เริ่มเว็บ
Start.command          ตัวเปิดสำหรับ macOS
```

## ทดสอบ

บน macOS / Linux รัน `sh test.sh` ต้องมี Python 3 เพิ่มเติมเฉพาะการทดสอบ API ชุดทดสอบใช้ฐานข้อมูลชั่วคราวและพอร์ตว่างแยก ไม่แก้ไขข้อมูลการเล่นจริง

- `ChallengeTest.java`: ตรวจขั้นตอน Bubble Sort, LIFO/FIFO ทั้ง 15 ด่าน การแฮชรหัสผ่าน และข้อมูลที่บันทึกจริง
- `api_test.py`: เล่นจบทั้ง 15 ด่าน ตรวจการแยกข้อมูลผู้ใช้ คะแนน อันดับ คำตอบซ้ำ การส่งคำตอบพร้อมกัน และปิด–เปิดเซิร์ฟเวอร์ใหม่เพื่อทดสอบการคงอยู่ของข้อมูล
- ชุดทดสอบ Java/API ตรวจสถานะก่อนเพิ่มข้อมูลและผลของแต่ละขั้นตอน รวมถึงการตอบผิดและขั้นตอนสุดท้าย โดยไม่ส่งสถานะเฉลยก่อนตอบ

ทดสอบวงจรแอนิเมชันเพิ่มเติมด้วย Node.js: `node --test test/visualizer_test.js` ครอบคลุมการเล่นซ้ำ ข้ามภาพ ยกเลิกเมื่อออกจากหน้า ค่าซ้ำใน Bubble Sort และการลดภาพเคลื่อนไหว

## ขอบเขตเวอร์ชันนี้

เป็นเกมฝึกแบบผู้เล่นคนเดียวแล้วเปรียบเทียบอันดับ โจทย์แต่ละด่านกำหนดไว้ล่วงหน้าและเล่นซ้ำได้ Stack และ Queue ใช้สถานการณ์เพิ่ม–นำข้อมูลออก โดยให้ตอบตัวที่จะถูกนำออก ฐานข้อมูลเก็บข้อมูลด่าน ส่วนขั้นตอนและเฉลยสร้างด้วยคลาส Java

ยังไม่มีการแข่งขันสดหลายคน ระบบเพิ่มโจทย์ผ่านหน้าผู้ดูแล เซิร์ฟเวอร์บนเครื่องรับการเชื่อมต่อจากเครื่องนี้โดยค่าเริ่มต้น ส่วน Docker ตั้งให้รับการเชื่อมต่อจากโฮสต์และใช้ secure cookie ผ่าน HTTPS ของ Render โดย session อยู่ในหน่วยความจำและต้องเข้าสู่ระบบใหม่หลังเซิร์ฟเวอร์เริ่มใหม่
